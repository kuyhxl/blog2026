# blog2026 디자인 소스

Claude Design 프로젝트 "기술 블로그 화면 디자인"의 화면 소스다.
원본: https://claude.ai/artifact/Mv5WWdpkHP6Qxraxwnf2Cn (2026-10-04 기준)

Claude Design의 공식 내보내기가 아니라 디자인 소스 파일을 그대로 모은 것이다.

## 구현 대상은 v2

| 폴더 | 내용 | 용도 |
|---|---|---|
| `screens/` | v2 · 녹색 바탕 · 소나무 | **구현 기준** |
| `screens/wrappers/` | 다크 모드와 검색 상태를 보여주는 얇은 파일 | 참고 |
| `archive-v1/` | v1 · 회색 바탕 | 보관용. 구현하지 않는다 |
| `canvas.json` | 캔버스의 화면 배치와 이름 | 참고 |

## 화면 파일

| 화면 | 데스크톱 (1440) | 모바일 (390) |
|---|---|---|
| 홈 | `HomeV2.dc.html` | `HomeV2M.dc.html` |
| 글 목록 | `MainV2.dc.html` | `MainV2M.dc.html` |
| 글 본문 | `PostV2.dc.html` | `PostV2M.dc.html` |
| Beauty of CS | `BeautyOfCSV2.dc.html` | `BeautyOfCSV2M.dc.html` |
| 검색 창 (부품) | `SearchV2.dc.html` | 같은 파일. 좁으면 화면을 가득 채운다 |
| 파비콘 | `FaviconV2.dc.html` | 아래 "파비콘" 참고 |

- 검색은 별도 페이지가 아니라 모든 화면 위에 겹쳐 뜨는 창이다. 각 화면이 `SearchV2`를 불러 쓴다
- `wrappers/`의 `*Dark` 파일은 같은 화면을 `theme="dark"`로, `Search*` 파일은 홈 화면을 검색 창이 열린 상태로 불러오기만 한다. 다크 모드의 실제 값은 각 화면 파일의 `.bx.dark{…}`에 있다

## 파일 형식

- `.dc.html`은 Claude Design의 화면 형식이다. `<x-dc>` 안의 마크업과 `<style>`, 그리고 `<script type="text/x-dc">` 안의 `DCLogic` 클래스로 이루어진다
- `./support.js`는 Claude Design의 실행 환경이라 여기에 없다. 그래서 **브라우저에서 바로 열리지 않는다.** 실제 모습은 위 원본 링크에서 확인한다
- 이 파일들은 실행하려는 것이 아니라 **읽고 옮기기 위한 명세**다. 마크업 구조, CSS, 동작 로직, 주석을 읽어 Next.js 컴포넌트로 다시 만든다. `DCLogic`이나 `x-dc` 문법을 그대로 가져가지 않는다
- 주석이 자세하다. 동작의 의도는 코드보다 주석을 먼저 읽는다
- 모바일 파일은 넓은 창에서도 휴대폰 폭으로 보이도록 가운데 390px로 묶여 있다. 구현할 때는 묶지 않는다
- 데스크톱 파일의 홈, 글 목록, 글 본문에는 1200px와 900px 구간의 좁은 화면용 CSS가 있다. 데스크톱과 모바일 시안 사이의 폭은 이 구간과 모바일 시안을 참고해 잇는다

## 디자인 토큰

각 화면 `<style>` 앞부분의 `.bx{…}`(라이트)와 `.bx.dark{…}`(다크)에 있다.

- 바탕 `--bg` 라이트 `#E3ECE4`, 다크 `#162119`
- 박스 면 `--panel`, 창 제목 줄 `--sunken`
- 글자 3단계 `--ink`, `--ink-2`, `--ink-3`
- 선 `--line`, `--line-2`, 점 격자 `--dot`, 호버 띠 `--hover`
- 소나무 `--pine-1~3`, `--bark-1~2` (다크에서는 밤의 색)
- 커서 효과 `--fx` 라이트 `rgb(74,128,92)`, 다크 `rgb(149,205,166)`
- 글꼴: 본문 `IBM Plex Sans KR`, 고정폭 `IBM Plex Mono` (Google Fonts)

## 구현되어 있는 동작

**모든 화면 공통**
- 헤더: 사이트 이름, `[B] Blog`, `[C] Beauty of CS`, Search(⌘K 또는 Ctrl+K), 테마 전환. 단축키는 한글 입력 상태에서도 동작하고, 글자를 입력하는 자리에서는 받지 않는다. 모바일에서는 `[키]` 표시 없이 이름만
- 픽셀 아트 소나무: 64×48칸, 색을 변수로 준 사각형. 데스크톱은 한 칸 4px, 좁은 화면은 3px, 2px
- 커서 효과: 14px 격자에 찍히는 테두리 네모가 20px에서 4px로 작아지며 0.8초 동안 사라진다(가장 진할 때 55%). 커서 아래에는 6px 네모. 누르면 4px에서 24px로 0.65초 동안 퍼진다. 터치와 펜은 잔상 없이 누름 효과만. "동작 줄이기"가 켜져 있으면 그리지 않는다

**홈**
- 자기소개, 최신 글 다섯 개(글 목록과 같은 행), Beauty of CS 입구(지도의 왼쪽 위 일부를 같은 규칙으로 그린 미리 보기)

**글 목록**
- 행 펼침(요약, 태그, Read), 태그 필터, 날짜순·이름순 정렬
- 브레인 맵 창: 점이 천천히 떠다니고 끌어서 옮길 수 있다. 행이나 점에 마우스를 올리면 강조, 필터에 걸리지 않은 글은 흐리게. 크게 보기 포함
- 모바일: 필터는 옆으로 미는 줄, 브레인 맵 창은 접혀 있다가 누르면 펼쳐진다. 점은 한 번 누르면 고르고, 다시 누르면 글로 이동한다

**글 본문**
- 스크롤에 따라 현재 항목이 바뀌는 목차
- FIG. 01 창: 현재 글과 직접 연결된 글의 그래프
- 본문 아래 백링크, 이전·다음 글, 댓글 영역(모양만 있는 시안)
- 모바일: 목차와 FIG. 01 창이 본문 위로 올라와 접혀 있다

**검색 창**
- 입력 전, 결과 있음, 결과 없음 상태
- 화살표 키로 행 이동, Enter로 열기, Tab은 창 안에서만 돈다. 바깥을 누르면 닫힌다. 열려 있는 동안 뒤 화면은 스크롤되지 않는다
- 정렬: 제목, 태그, 요약 순으로 일치한 글이 앞에 오고, 같으면 최신 글이 먼저
- 시안은 제목·요약·태그에서만 찾는다. 실제 구현은 본문까지 찾고, 일치한 문장의 둘레를 잘라 보여 준다

**Beauty of CS**
- `cs-map-graph.json`의 노드와 연결선이 스크립트 안에 그대로 들어 있다
- 과목 구역 배치, 큰 개념을 누르면 세부 개념이 펼쳐진다
- 선수 지식(실선 화살표)과 연관 개념(점선)의 길 내기 규칙, 확대·축소와 Fit
- 개념을 고르면 요약 패널
- 모바일: 한 손가락으로 이동, 두 손가락으로 확대·축소. 요약 패널은 화면 아래에서 올라오고 손잡이를 끌어 반 또는 전체 높이로 맞춘다

## 파비콘

`screens/FaviconV2.dc.html`은 시안 셋을 견주어 보는 판이다. 판 자체(확대한 모습, 탭 모형, 홈 화면 줄)는 구현 대상이 아니고, 그 안의 **격자와 색**만 옮긴다.

- 시안: A 투명 배경, B 옅은 녹색 바탕(`#E3ECE4`), C 어두운 녹색 바탕(`#162119`)과 밤의 소나무 색
- **어느 시안을 쓸지는 이 파일에 적혀 있지 않다. 사용자에게 확인한다**
- 격자는 스크립트 맨 위의 `G16`(16×16칸), `G32`(32×32칸), `G180`(30×30칸, 한 칸 6px로 180×180)에 있다. 한 글자가 한 칸이고 첫 줄 첫 글자가 왼쪽 위다
  - `.` 빈 칸 (A는 투명, B와 C는 바탕색)
  - `1` `2` `3` 잎: `--pine-1`(밝음), `--pine-2`, `--pine-3`(어두움)
  - `a` `b` 줄기: `--bark-1`(밝음), `--bark-2`(어두움)
- 색 값은 `<style>`의 `.day`(A와 B)와 `.night`(C)에 있다
- 글자를 색으로 바꾸는 표는 `FULL`과 `NIGHT_SMALL`이다. C의 16칸과 32칸은 어두운 바탕에 묻히지 않게 색 단계를 줄인 `NIGHT_SMALL`을 쓴다
- 180×180은 홈 화면용이라 빈 칸까지 바탕색으로 채운다. A를 골라도 180은 B와 같은 그림이다
- SVG로 옮길 때: `viewBox="0 0 N N"`, `shape-rendering="crispEdges"`, 칸마다 1×1 사각형. 흐림이나 반투명 없이

## 주의

- 글 제목, 요약, 날짜, 연결 관계, 댓글은 전부 화면 확인용 샘플이다. 소스 안에서 `posts-data`, `map-data`, `cs-data` 표시로 감싸 둔 부분이 샘플 데이터다. 실제 데이터는 `content/`의 공개 노트에서 만든다
- 홈의 `[사이트 이름]`과 `[자기소개 한두 문장]`은 아직 정해지지 않은 자리다. 지어내지 말고 물어본다
- "캔버스에서 편집하는 중" 같은 분기와 `search="open"`, `map="open"` 같은 시작 상태 값은 Claude Design 안에서만 의미가 있으니 옮기지 않는다
