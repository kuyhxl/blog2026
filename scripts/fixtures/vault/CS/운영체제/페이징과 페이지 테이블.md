# 페이징과 페이지 테이블

프로세스가 보는 주소는 실제 메모리의 주소가 아니다. 운영체제는 프로세스마다 0번지에서 시작하는 주소 공간을 따로 내어 주고, CPU는 메모리에 접근할 때마다 그 주소를 실제 위치로 바꾼다.

## 왜 주소를 한 번 더 감싸는가

모든 프로세스가 물리 주소를 그대로 쓴다면 두 가지 문제가 생긴다. 자세한 사례는 [[MySQL 데드락 로그를 읽고 원인을 찾은 과정]]에도 나온다. 실행 계획 이야기는 [[EXPLAIN 읽는 법|EXPLAIN 정리]], 그 가운데 [[EXPLAIN 읽는 법#type 컬럼]]을 본다.

면접 때 정리한 내용은 [[PRIVATE 면접 준비|면접 정리]]에 있고, 회사에서 겪은 일은 [[개인/PRIVATE 회사 메모|사내 정리]]에 있다. [[없는 노트 SECRET-MISSING|아직 쓰지 않은 글]]도 있고, [지난 회고](개인/PRIVATE%20면접%20준비.md)도 있다. 트리 구조는 [[트리]] 노드에서 다룬다.

## 페이지와 프레임

가상 주소 공간을 고정된 크기로 자른 조각을 **페이지**, 물리 메모리를 같은 크기로 자른 조각을 **프레임**이라 한다. 페이지 크기가 4KB, 곧 $2^{12}$바이트라면 하위 12비트가 오프셋이다. 2<sup>20</sup>개의 페이지가 생긴다.

$$
\text{물리 주소} = \text{PFN} \times 2^{12} + \text{offset}
$$

### 비트로 나누기

- `VPN` 페이지 테이블에서 엔트리를 찾는 인덱스로 쓰인다.
- `PFN` 그 페이지가 실제로 들어 있는 프레임의 번호다.
- `offset` 페이지 안에서의 위치다.

## 페이지 테이블 엔트리

| Bit | Name | Meaning |
| --- | --- | --- |
| 0 | P · Present | 페이지가 물리 메모리에 있다. 자세히는 [[EXPLAIN 읽는 법\|EXPLAIN]] 참고 |
| 1 | R/W | 쓰기를 허용한다. ==0이면 읽기 전용==이다. |
| 63 | NX | 이 페이지의 내용을 코드로 실행하지 못한다.[^nx] |

[^nx]: AMD가 먼저 도입했고, 인텔은 XD 비트라고 부른다.

## 변환을 코드로 옮기면

```c title=translate.c
#define PAGE_SHIFT     12                         // 4KB = 2^12
#define OFFSET_MASK    ((1UL << PAGE_SHIFT) - 1)

uint64_t translate(const uint64_t *page_table, uint64_t vaddr) {
    uint64_t vpn    = vaddr >> PAGE_SHIFT;        // 가상 페이지 번호
    uint64_t offset = vaddr & OFFSET_MASK;
    uint64_t pte = page_table[vpn];
    if (!(pte & 0x1UL))
        return page_fault(vaddr);                 // [[링크 아님]] %% 주석 아님 %%
    return (pte & ~0xFFFUL) | offset;
}
```

```ts
// TypeScript로 옮기면
export function vpn(vaddr: bigint): bigint {
  return vaddr >> 12n;
}
```

> [!note]
> P 비트가 0이라고 해서 잘못된 접근인 것은 아니다. 아직 메모리에 올리지 않았거나 디스크로 내보낸 페이지일 수도 있다.

> [!warning] 직접 붙인 제목
> TLB를 비우지 않고 페이지 테이블만 바꾸면 **오래된 변환**이 남는다.

> [!tip]- 접어 둔 콜아웃
> 펼치면 보이는 내용이다. `invlpg` 명령어를 찾아본다.

> 일반 인용문은 콜아웃이 아니다.
